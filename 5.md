# Báo cáo Phân tích Lỗi UX Tìm kiếm Bệnh nhân (/patients) và Phản biện Giải pháp của 1.md

Sau khi đối chiếu chi tiết mã nguồn hiện tại của dự án và báo cáo đề xuất trong file [1.md](file:///d:/skul9x/QLPK-SaaS-main/1.md), em phát hiện ra một **lỗi logic nghiêm trọng (Bug tiềm ẩn)** trong phương án khắc phục của `1.md` liên quan đến việc xử lý sự kiện Back/Forward của trình duyệt.

Dưới đây là phân tích chi tiết mã nguồn, lỗi của `1.md` và giải pháp sửa đổi tối ưu nhất.

## 1. Phân tích Lỗi tiềm ẩn trong Giải pháp 1 của `1.md`

File `1.md` đề xuất giải pháp cập nhật [PatientSearch.tsx](file:///d:/skul9x/QLPK-SaaS-main/src/components/features/patients/PatientSearch.tsx) như sau:

```typescript
// Lấy từ 1.md
const lastSearchedTerm = useRef(initialValue);

// Effect 1: Đồng bộ ngược từ URL
useEffect(() => {
  if (initialValue !== lastSearchedTerm.current) {
    setSearchTerm(initialValue);
    lastSearchedTerm.current = initialValue;
  }
}, [initialValue]);

// Effect 2: Kích hoạt tìm kiếm khi debounced thay đổi hoặc onSearch thay đổi
useEffect(() => {
  lastSearchedTerm.current = debouncedSearchTerm;
  onSearch(debouncedSearchTerm);
}, [debouncedSearchTerm, onSearch]);
```

### Kịch bản gây lỗi "Không thể nhấn nút Back" (Back Button Loop Bug):

Giả sử người dùng đang ở trang `/patients?q=Tuấn` và bấm nút **Back** của trình duyệt để quay lại trang danh sách gốc `/patients` (không có từ khóa tìm kiếm):

1. Trình duyệt quay lại `/patients`, URL thay đổi khiến `searchParams` thay đổi.
2. Tại component cha `PatientListClient`, callback `handleSearch` phụ thuộc vào `searchParams` nên nó được **tạo mới (new reference)**.
3. Component `PatientSearch` re-render và nhận:
   - `initialValue` mới là `""` (chuỗi rỗng).
   - Prop `onSearch` mới (ref mới từ `handleSearch`).
4. React lên lịch chạy cả hai Effect: **Effect 1** (do `initialValue` thay đổi) và **Effect 2** (do `onSearch` thay đổi).
5. **Effect 1 chạy trước:**
   - So sánh `initialValue` (`""`) với `lastSearchedTerm.current` (`"Tuấn"`).
   - Thấy khác nhau, gọi `setSearchTerm("")` và gán `lastSearchedTerm.current = ""`.
6. **Effect 2 chạy ngay sau đó trong cùng lượt render:**
   - Lúc này, mặc dù `setSearchTerm("")` đã được gọi, nhưng component **chưa re-render** để cập nhật `debouncedSearchTerm`. Vì vậy, `debouncedSearchTerm` vẫn giữ giá trị cũ là `"Tuấn"`.
   - Effect 2 thực hiện gán đè: `lastSearchedTerm.current = debouncedSearchTerm` (gán lại thành `"Tuấn"`).
   - Gọi `onSearch("Tuấn")`.
7. Callback `onSearch("Tuấn")` chạy, thấy từ khóa tìm kiếm `"Tuấn"` khác với query hiện tại trên URL (`""`), nó lập tức kích hoạt `router.replace('/patients?q=Tuấn')`.
8. **Kết quả:** Người dùng vừa nhấn Back để quay về trang trống thì lập tức bị ứng dụng **tự động chuyển hướng ngược trở lại** trang tìm kiếm `/patients?q=Tuấn`. Người dùng không thể quay lại trang trước đó bằng nút Back của trình duyệt.

## 2. Giải pháp Khắc phục Triệt để và An toàn

Để khắc phục cả lỗi giật chữ khi gõ lẫn lỗi vòng lặp nút Back ở trên, chúng ta cần:
1. **Ổn định hóa callback `onSearch`:** Sử dụng một `useRef` để giữ tham chiếu đến `onSearch` mới nhất.
2. **Loại bỏ `onSearch` khỏi danh sách dependency** của Effect kích hoạt tìm kiếm, đảm bảo Effect này chỉ chạy khi người dùng thực sự nhập chữ (`debouncedSearchTerm` thay đổi).

### Code sửa đổi chuẩn xác cho `src/components/features/patients/PatientSearch.tsx`:

```tsx
'use client';

import React, { useState, useEffect, useRef } from 'react';
import { HiOutlineMagnifyingGlass, HiOutlineXMark, HiOutlineArrowPath } from 'react-icons/hi2';
import { useDebounce } from '@/hooks/useDebounce';
import { cn } from '@/lib/utils/cn';

interface PatientSearchProps {
  onSearch: (term: string) => void;
  initialValue?: string;
  placeholder?: string;
  isLoading?: boolean;
}

export default function PatientSearch({ 
  onSearch, 
  initialValue = '', 
  placeholder = 'Tìm theo tên hoặc số điện thoại...',
  isLoading = false
}: PatientSearchProps) {
  const [searchTerm, setSearchTerm] = useState(initialValue);
  const debouncedSearchTerm = useDebounce(searchTerm, 300);
  
  // Lưu giữ giá trị tìm kiếm đã gửi đi gần nhất
  const lastSearchedTerm = useRef(initialValue);

  // Giữ tham chiếu ổn định đến callback onSearch mới nhất
  const onSearchRef = useRef(onSearch);
  useEffect(() => {
    onSearchRef.current = onSearch;
  }, [onSearch]);

  // Effect 1: Chỉ đồng bộ ngược từ URL khi có sự thay đổi ngoại cảnh (như nhấn Back/Forward)
  useEffect(() => {
    if (initialValue !== lastSearchedTerm.current) {
      setSearchTerm(initialValue);
      lastSearchedTerm.current = initialValue;
    }
  }, [initialValue]);

  // Effect 2: Chỉ kích hoạt tìm kiếm khi người dùng thực sự thay đổi nội dung ô nhập liệu
  useEffect(() => {
    // Tránh trigger lại tìm kiếm ban đầu lúc mới mount nếu giá trị trùng khớp
    if (debouncedSearchTerm === lastSearchedTerm.current) return;

    lastSearchedTerm.current = debouncedSearchTerm;
    onSearchRef.current(debouncedSearchTerm);
  }, [debouncedSearchTerm]);

  const handleClear = () => {
    setSearchTerm('');
  };

  return (
    <div className="relative w-full">
      <div className="absolute inset-y-0 left-0 pl-3 flex items-center pointer-events-none">
        {isLoading ? (
          <HiOutlineArrowPath className="h-5 w-5 text-primary-500 animate-spin" aria-hidden="true" />
        ) : (
          <HiOutlineMagnifyingGlass className="h-5 w-5 text-gray-400" aria-hidden="true" />
        )}
      </div>
      <input
        type="text"
        className={cn(
          "input-field pl-10 pr-10",
          "bg-surface dark:bg-surface-dark"
        )}
        placeholder={placeholder}
        value={searchTerm}
        onChange={(e) => setSearchTerm(e.target.value)}
      />
      {searchTerm && (
        <button
          type="button"
          onClick={handleClear}
          className="absolute inset-y-0 right-0 pr-3 flex items-center text-gray-400 hover:text-gray-600 dark:hover:text-gray-200 transition-colors"
        >
          <HiOutlineXMark className="h-5 w-5" aria-hidden="true" />
        </button>
      )}
    </div>
  );
}
```

### Tại sao giải pháp này an toàn?
- Khi người dùng bấm **Back**: `initialValue` thay đổi thành `""`. **Effect 1** chạy và đặt `searchTerm = ""`, `lastSearchedTerm.current = ""`.
- Do `onSearch` không nằm trong danh sách dependency của **Effect 2**, Effect 2 không bị kích hoạt chạy ngay lập tức với giá trị `debouncedSearchTerm` cũ.
- Khi component re-render với `searchTerm = ""`, sau 300ms `debouncedSearchTerm` chuyển thành `""`.
- **Effect 2** được kích hoạt do `debouncedSearchTerm` thay đổi. Nó kiểm tra điều kiện: `debouncedSearchTerm === lastSearchedTerm.current` (tức là `"" === ""`).
- Vì điều kiện trùng khớp, Effect 2 dừng lại (`return`) và **không** gọi `onSearchRef.current("")`, giúp tránh hoàn toàn vòng lặp redirect và giữ nút Back hoạt động chính xác.
