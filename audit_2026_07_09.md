## 🔴 Critical Issues (Phải sửa NGAY)

### 1. 🚨 RLS bị TẮT trên 4 bảng chứa dữ liệu nhạy cảm nhất

> **Triệu chứng:** Bảng `patients`, `medicines`, `prescriptions_header`, `prescription_details` đã có policy RLS nhưng **RLS bị DISABLED** trong database thật.

- **File/Nơi xảy ra:** Database Production (kiểm tra qua Supabase MCP)
- **Bảng bị ảnh hưởng:**

| Bảng | RLS Status | Dữ liệu chứa |
|------|-----------|---------------|
| `patients` | ❌ `false` | Tên, SĐT, ngày sinh, địa chỉ, tiền sử bệnh |
| `medicines` | ❌ `false` | Kho thuốc, giá thuốc |
| `prescriptions_header` | ❌ `false` | Đơn thuốc, chẩn đoán, doanh thu |
| `prescription_details` | ❌ `false` | Chi tiết đơn thuốc |

- **🔥 Nguy hiểm (Giải thích đời thường):** Dù anh đã viết "luật" bảo vệ dữ liệu (RLS policies), nhưng "công tắc" để bật luật đó đang **TẮT**. Giống như có khóa cửa nhưng không gài khóa. Bất kỳ user đã đăng nhập nào (kể cả tài khoản clinic khác) đều có thể **đọc, sửa, xóa** toàn bộ dữ liệu bệnh nhân của clinic khác.

- **Nguyên nhân có thể:** Một migration sau (có thể `20260624000001` hoặc bảng được tạo lại) đã vô tình disable RLS hoặc chưa enable lại.

- **Cách sửa:** Chạy SQL migration:
```sql
ALTER TABLE patients ENABLE ROW LEVEL SECURITY;
ALTER TABLE medicines ENABLE ROW LEVEL SECURITY;
ALTER TABLE prescriptions_header ENABLE ROW LEVEL SECURITY;
ALTER TABLE prescription_details ENABLE ROW LEVEL SECURITY;
```

### 2. 🚨 Role `anon` vẫn có FULL quyền trên 6 bảng

> **Triệu chứng:** Mặc dù đã có migration `20260511_emergency_revoke_anon.sql`, role `anon` vẫn giữ quyền INSERT/SELECT/UPDATE/DELETE/TRUNCATE trên nhiều bảng.

- **Bảng bị ảnh hưởng:**

| Bảng | Quyền anon đang có |
|------|-------------------|
| `patients` | INSERT, SELECT, UPDATE, DELETE, TRUNCATE |
| `medicines` | INSERT, SELECT, UPDATE, DELETE, TRUNCATE |
| `prescriptions_header` | INSERT, SELECT, UPDATE, DELETE, TRUNCATE |
| `prescription_details` | INSERT, SELECT, UPDATE, DELETE, TRUNCATE |
| `clinic_daily_stats` | INSERT, SELECT, UPDATE, DELETE, TRUNCATE |
| `medicine_dosage_cache` | INSERT, SELECT, UPDATE, DELETE, TRUNCATE |
| `legacy_prescription_images` | INSERT, SELECT, UPDATE, DELETE, TRUNCATE |

- **🔥 Nguy hiểm:** Bất kỳ ai có `anon key` (key này nằm công khai trong frontend code `NEXT_PUBLIC_SUPABASE_ANON_KEY`) đều có thể **truy cập trực tiếp database** mà **KHÔNG CẦN đăng nhập**. Kết hợp với vấn đề #1 (RLS tắt), **hacker có thể đọc/xóa toàn bộ dữ liệu bệnh nhân chỉ bằng anon key**.

- **Nguyên nhân:** Có migration nào đó (có thể `20260624...`) đã chạy `GRANT ALL` lại sau khi revoke, hoặc migration revoke chưa được áp dụng thành công.

- **Cách sửa:**
```sql
-- Thu hồi toàn bộ quyền anon
REVOKE ALL ON ALL TABLES IN SCHEMA public FROM anon;
REVOKE ALL ON ALL SEQUENCES IN SCHEMA public FROM anon;
REVOKE ALL ON ALL FUNCTIONS IN SCHEMA public FROM anon;

-- Chỉ cho phép truy cập schema (cần cho auth flow)
GRANT USAGE ON SCHEMA public TO anon;
```

### 3. 🚨 Middleware Next.js không hoạt động - Không có bảo vệ route

> **Triệu chứng:** File middleware đặt tại `src/proxy.ts` với function tên `proxy`, nhưng **KHÔNG có** file `middleware.ts` ở root hoặc `src/` → Next.js không nhận.

- **File:** [proxy.ts](file:///home/skul9x/Desktop/Test_code/QLPK-SaaS-main/src/proxy.ts)
- **🔥 Nguy hiểm:** Middleware làm 2 việc quan trọng:
  1. **Refresh token** tự động → Không có middleware, user có thể bị logout bất ngờ
  2. **Chặn truy cập** vào trang dashboard khi chưa đăng nhập → Hiện tại **ai cũng có thể vào bất kỳ trang nào** (trang patients, medicines...) mà không cần đăng nhập. Dù server actions check auth, nhưng trang vẫn render được.
  
- **Cách sửa:** Đổi tên file `src/proxy.ts` → `src/middleware.ts` và đổi export:
```typescript
// src/middleware.ts
import { type NextRequest } from 'next/server'
import { updateSession } from '@/lib/supabase/proxy'

export async function middleware(request: NextRequest) {
  return await updateSession(request)
}

export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
}
```

## 🟡 Warnings (Nên sửa sớm)

### 4. ⚠️ Không có Rate Limiting cho đăng nhập

- **File:** [auth.ts](file:///home/skul9x/Desktop/Test_code/QLPK-SaaS-main/src/actions/auth.ts)
- **Vấn đề:** Không tìm thấy bất kỳ cơ chế rate limiting nào cho login endpoint. Hacker có thể thử đăng nhập liên tục (brute-force) hàng nghìn lần/phút.
- **Hậu quả:** Nếu mật khẩu yếu (6 ký tự), hacker có thể đoán được trong vài giờ.
- **Lưu ý:** Supabase Auth có rate limiting mặc định (tối đa ~30 lần/giờ), nhưng nên thêm lớp bảo vệ ở tầng application nữa.
- **Cách sửa:** Thêm rate limiting bằng in-memory store hoặc Redis, hoặc sử dụng Supabase Edge Functions với rate limit. Tối thiểu, kiểm tra config Supabase Auth rate limit tại Dashboard → Auth → Rate Limits.

### 6. ⚠️ CSP (Content-Security-Policy) cho phép `unsafe-inline` và `unsafe-eval`

- **File:** [next.config.ts:26-28](file:///home/skul9x/Desktop/Test_code/QLPK-SaaS-main/next.config.ts#L26-L28)
- **Giá trị hiện tại:**
```
script-src 'self' 'unsafe-inline' 'unsafe-eval'
```
- **Vấn đề:** `unsafe-inline` và `unsafe-eval` làm giảm đáng kể hiệu quả của CSP. Nếu có lỗ hổng XSS, hacker vẫn có thể chạy script độc.
- **Lưu ý:** Đây là vấn đề phổ biến với Next.js vì framework cần inline scripts. Có thể cải thiện bằng `nonce-based` CSP.
- **Mức độ:** Medium - Không phải lỗ hổng trực tiếp nhưng làm suy yếu phòng thủ.

## 🟢 Suggestions (Tùy chọn - Nâng cao bảo mật)

### 8. 💡 Input validation tốt nhưng chưa sanitize HTML

- **Vấn đề:** Các field text (patient name, diagnosis, address) được validate bằng Zod (✅ tốt) nhưng không sanitize HTML tags. React tự escape khi render (✅ an toàn với JSX), nhưng nếu dữ liệu được dùng ở nơi khác (PDF export, email...) thì có thể bị XSS.
- **Cách sửa:** Thêm `.transform(val => val.replace(/<[^>]*>/g, ''))` vào Zod schema cho các trường text.

### 9. 💡 RPCs sử dụng `SECURITY DEFINER` nhưng không set `search_path`

- **File:** [20260427181500_rls_redesign.sql](file:///home/skul9x/Desktop/Test_code/QLPK-SaaS-main/supabase/migrations/20260427181500_rls_redesign.sql)
- **Vấn đề:** Các RPC functions (`upsert_patient`, `create_prescription`, `merge_patients`...) dùng `SECURITY DEFINER` nhưng không set `search_path = public`. Điều này có thể bị khai thác bằng search_path injection trong một số trường hợp.
- **Lưu ý:** `get_my_clinic_id()` đã được fix đúng (có `SET search_path = public`), nhưng các RPC khác chưa có.

### 10. 💡 API endpoint `/api/medicine-dosage` thiếu rate limiting riêng

- **File:** [route.ts](file:///home/skul9x/Desktop/Test_code/QLPK-SaaS-main/src/app/api/medicine-dosage/route.ts)
