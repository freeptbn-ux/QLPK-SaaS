# BÁO CÁO PHÂN TÍCH UX FLOW SEARCH TẠI /PATIENTS VÀ PHƯƠNG ÁN KHẮC PHỤC

## 1. Nguyên nhân chi tiết (Root Cause Analysis)

Hiện tại, chức năng tìm kiếm bệnh nhân tại trang `/patients` gặp hiện tượng **nhảy/revert kết quả và reload liên tục** khi người dùng gõ nhanh, gõ nhầm hoặc xóa đi nhập lại. Hiện tượng này xảy ra do hai nguyên nhân chính:

### Nguyên nhân A: Đồng bộ hóa trạng thái (Race Condition / Blind State Sync)
Trong component [PatientSearch.tsx](file:///d:/skul9x/QLPK-SaaS-main/src/components/features/patients/PatientSearch.tsx):
```typescript
// Lấy giá trị khởi tạo từ URL thông qua component cha chuyển xuống
const [searchTerm, setSearchTerm] = useState(initialValue);
const debouncedSearchTerm = useDebounce(searchTerm, 300);

// useEffect tự động cập nhật lại ô input khi initialValue thay đổi
useEffect(() => {
  setSearchTerm(initialValue);
}, [initialValue]);
```
Quy trình lỗi xảy ra như sau:
1. Người dùng gõ chữ `Tuấn` vào ô tìm kiếm.
2. Trải qua 300ms trì hoãn (debounce), `debouncedSearchTerm` chuyển thành `Tuấn`.
3. `useEffect` gọi hàm `onSearch("Tuấn")`, kích hoạt `router.replace('/patients?q=Tuấn')` để tải lại dữ liệu từ Server Components.
4. Trong khi Server đang xử lý truy vấn tìm `Tuấn` (mất khoảng vài trăm ms), người dùng nhận ra họ gõ nhầm và bấm phím xóa (backspace) thành `Tu`.
5. Server hoàn thành yêu cầu tìm `Tuấn` và trả về danh sách kết quả mới cho Client.
6. Trang web cập nhật. Component cha render lại và truyền prop `initialValue="Tuấn"` vào `PatientSearch`.
7. `useEffect` đồng bộ hóa chạy: `setSearchTerm("Tuấn")`.
8. **Lỗi UX xuất hiện:** Giá trị trong ô input đột ngột bị giật ngược (jump) từ `Tu` trở lại `Tuấn` mặc dù người dùng đang gõ dở.

### Nguyên nhân B: Sử dụng Server-side Routing thay vì Client-side Filtering
* **Tại kê đơn (Medicine):** Tất cả danh sách thuốc được tải về client **một lần duy nhất** khi mở trang (thông qua `getMedicinesForSearch()`). Việc lọc và tìm kiếm được thực hiện hoàn toàn ở Client-side (sử dụng `.filter` trong JS). Nó có ưu điểm là **tốc độ phản hồi tức thì (instant), không có độ trễ mạng, không tải lại component**.
* **Tại bệnh nhân (Patients):** Lượt truy vấn tìm kiếm được gửi về server (thông qua Next.js Server Components + Server Actions + Supabase RPC). Mỗi lần tìm kiếm là một lần Next.js render lại toàn bộ component tree của trang `/patients`. Do đó có độ trễ mạng (Network Latency), gây ra hiện tượng reload và hiển thị spinner liên tục.

## 2. Có nên cấu hình Search bệnh nhân giống như gõ tên thuốc không?

### Phân tích so sánh:
* **Medicines (Danh mục thuốc):** Thường có số lượng giới hạn và ổn định (vài chục đến vài trăm loại thuốc trong một phòng khám). Tải tất cả về Client một lần là giải pháp tối ưu.
* **Patients (Danh sách bệnh nhân):** Số lượng bệnh nhân tăng dần theo thời gian sử dụng dịch vụ (SaaS). Một phòng khám hoạt động lâu dài có thể có hàng nghìn hoặc hàng chục nghìn hồ sơ bệnh nhân.
  * Nếu tải **tất cả** bệnh nhân về Client 1 lần:
    * **Tốc độ tải trang lần đầu cực kỳ chậm** (tải file JSON dung lượng lớn).
    * **Tốn bộ nhớ trình duyệt** gây giật lag thiết bị.
    * Dữ liệu bệnh nhân mới thêm bởi nhân viên khác không được cập nhật kịp thời.
  * Vì vậy, **viết Server-side Search + Phân trang (Pagination) cho bệnh nhân là giải pháp đúng đắn về mặt kiến trúc phần mềm**. Tuy nhiên cần tối ưu lại để loại bỏ lỗi giật lag UX.

## 3. Cách khắc phục lỗi giật/nhảy kết quả (Proposed Solutions)

Có 2 hướng tiếp cận để xử lý triệt để lỗi UX này:

### Phương án 1: Ngăn chặn ghi đè Input khi đang gõ (Khuyên dùng - Đơn giản nhất)
Chúng ta sẽ theo dõi giá trị được gửi tìm kiếm gần nhất. Chỉ cập nhật lại ô input từ URL (`initialValue`) khi người dùng điều hướng bằng nút quay lại của trình duyệt (Browser Back/Forward), chứ không cập nhật khi đang gõ.

#### Cập nhật file [PatientSearch.tsx](file:///d:/skul9x/QLPK-SaaS-main/src/components/features/patients/PatientSearch.tsx):
```tsx
'use client';

import React, { useState, useEffect, useRef } from 'react';
import { HiOutlineMagnifyingGlass, HiOutlineXMark, HiOutlineArrowPath } from 'react-icons/hi2';
import { useDebounce } from '@/hooks/useDebounce';
import { cn } from '@/lib/utils/cn';

interface PatientSearchProps {
  onSearch: (term: string) => void;
  initialValue?: string;
  placeholder?: string;
  isLoading?: boolean;
}

export default function PatientSearch({ 
  onSearch, 
  initialValue = '', 
  placeholder = 'Tìm theo tên hoặc số điện thoại...',
  isLoading = false
}: PatientSearchProps) {
  const [searchTerm, setSearchTerm] = useState(initialValue);
  const debouncedSearchTerm = useDebounce(searchTerm, 300);
  
  // Lưu trữ giá trị tìm kiếm đã gửi đi gần nhất để tránh đồng bộ ngược lại khi đang gõ
  const lastSearchedTerm = useRef(initialValue);

  // Chỉ đồng bộ hóa lại từ URL (prop initialValue) khi có sự thay đổi ngoại cảnh (ví dụ: Back/Forward trang)
  useEffect(() => {
    if (initialValue !== lastSearchedTerm.current) {
      setSearchTerm(initialValue);
      lastSearchedTerm.current = initialValue;
    }
  }, [initialValue]);

  useEffect(() => {
    lastSearchedTerm.current = debouncedSearchTerm;
    onSearch(debouncedSearchTerm);
  }, [debouncedSearchTerm, onSearch]);

  const handleClear = () => {
    setSearchTerm('');
  };

  return (
    <div className="relative w-full">
      <div className="absolute inset-y-0 left-0 pl-3 flex items-center pointer-events-none">
        {isLoading ? (
          <HiOutlineArrowPath className="h-5 w-5 text-primary-500 animate-spin" aria-hidden="true" />
        ) : (
          <HiOutlineMagnifyingGlass className="h-5 w-5 text-gray-400" aria-hidden="true" />
        )}
      </div>
      <input
        type="text"
        className={cn(
          "input-field pl-10 pr-10",
          "bg-surface dark:bg-surface-dark"
        )}
        placeholder={placeholder}
        value={searchTerm}
        onChange={(e) => setSearchTerm(e.target.value)}
      />
      {searchTerm && (
        <button
          type="button"
          onClick={handleClear}
          className="absolute inset-y-0 right-0 pr-3 flex items-center text-gray-400 hover:text-gray-600 dark:hover:text-gray-200 transition-colors"
        >
          <HiOutlineXMark className="h-5 w-5" aria-hidden="true" />
        </button>
      )}
    </div>
  );
}
```

### Phương án 2: Tối ưu UI khi Server Component đang tải dữ liệu

### Phương án 3: Chuyển sang Tìm kiếm qua Client Fetch API (Sử dụng Client State)
Nếu muốn trang `/patients` có độ mượt tối đa như gõ tên thuốc mà không cần reload router:
1. Giữ nguyên Server-side search trên database để đảm bảo hiệu năng.
2. Tuy nhiên, thay vì sử dụng URL Query Parameter (`?q=...`) và `router.replace`, chúng ta sẽ fetch dữ liệu trực tiếp thông qua một API Route (hoặc gọi Server Action trực tiếp từ Client) và lưu kết quả vào một State cục bộ (`const [patients, setPatients] = useState()`).
3. Khi người dùng gõ tìm kiếm, ta chỉ cần gọi API đó và set lại state.
4. Cách này sẽ không thay đổi URL, trang không bao giờ bị nhảy/giật, giao diện cập nhật cực kỳ mượt mà.
